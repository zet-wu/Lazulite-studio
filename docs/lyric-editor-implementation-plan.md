# 歌词编辑器重构与 AMLL TTML Tool 对齐计划

日期：2026-09-25。状态：E0–E2 已验收，E3 起待实施。下文“当前实现与限制”表保留计划制定时的 `2ff3b2c` 基线；进度以[E0–E1 验收](editor-e0-e1-acceptance.md)、[E2 验收](editor-e2-acceptance.md)和[对齐矩阵](editor-parity.md)为准。

## 1. 目标与基线

下一阶段集中建设可日常使用的歌词编辑器，基本复刻 amll-ttml-tool 的前端布局和歌词编辑工作流，包括词块编辑、分词、Ruby、连续打轴、时间轴精修及预览。不能以“有同名面板/按钮”代替行为对齐，也不能在当前整行表单旁继续堆积功能。

本次按本地源码审阅：

- LazuliteStudio：`2ff3b2c`，开始审阅时工作区干净。
- amll-ttml-tool：`10b77c7`，开始审阅时工作区干净；下文简称“参考工具”。参考路径均相对于该仓库。
- [原实施计划](../../lyric-workflow/docs/lazulite_studio_implementation_plan.md)仍停留在 S1/S2 状态说明；Studio 的代码、README 和 S3–S7 验收文档已经覆盖后续阶段。S7 消费端仍有限制，与本次编辑器目标无关。
- 本次结论来自源码和已有验收记录，没有重新启动两套应用做逐屏比对，也没有重新运行历史测试。现有截图不是本轮运行证据。E0 必须补充参考工具运行基线。

本计划为下一阶段执行依据；与旧文档冲突时，编辑器布局、模型及旧数据兼容策略按本计划与根目录 AGENTS.md 执行。保留原 S1–S7 记录作为历史，不据其“已验收”推断编辑体验已经对齐。

## 2. 范围

**必须完成：** 编辑/打轴/预览模式，菜单与 Ribbon，词块和行直接编辑，选择与批量操作，行词拆合和排序，手动/自动/高级分词，翻译与音译，逐词音译分配，Ruby 创建/拆合/计时，背景/对唱歌词，时间偏移与平滑、时间链接，快捷键，音频试听、波形/频谱及可编辑时间轴，歌词元数据、文件导入导出、撤销保存闭环。

**保留并接入：** Studio 项目、媒体上传/代理、revision/ETag 保存、当前草稿恢复、多歌手，以及现有人工应用机器候选的入口。自动任务从主编辑画布移入辅助面板，不能成为手工分词或注音的前置条件。项目入口和品牌保留 Studio 身份。

**本轮不扩展：** ASR/forced 模型质量、GPU 后端、新的取词平台、发布封装与 MusicBox、多人协同、Tauri 桌面壳/更新器、上游投稿、遥测、PWA、主题壁纸市场。LRCLIB 联网搜索维持已有能力，不要求克隆其专用接入。歌词格式转换、BPM 辅助和频谱属于编辑工作流，不能因涉及媒体而无限后置。

## 4. 实现决策

### 4.1 一个编辑文档，直接替换旧模型

采用 **行 → 词块 → Ruby 读音单元** 的显式编辑模型。保留 Studio 多 agent 和整体 Ruby 语义，不直接把 AMLL 播放器模型当作持久化模型。建议在 `domain/document.ts` 定义：

| 对象 | 必要字段 / 规则 |
| --- | --- |
| Document | lines、agents、metadata、language；不把服务请求、播放时钟放入文档 |
| Line | 稳定 id、words、beginUs/endUs、agentRefs、backgroundOf、对唱显示属性、translations、romanizations |
| Word | 稳定 id、text、beginUs/endUs、romanization、rubyUnits、obscene、emptyBeat；无时间也必须能存在 |
| RubyUnit | 稳定 id、reading、beginUs/endUs；属于整个 Word 的 base，不强行对齐到单个汉字 |
| 编辑附属状态 | ignoreSync、时间链接的原值等需要重开恢复的编辑信息；放当前版本草稿元数据，最终交换文件不混入内部状态 |
| 会话状态 | 模式、选中行/词/读音 ID、焦点、锚点、拖动预览、播放位置；不进入文档撤销历史 |

行正文从 words 拼接得到；整体 reading 从 rubyUnits 拼接得到，禁止同时维护另一份可写 text/reading。空白作为明确的文本内容保存，不因分词和 join/trim 丢失空格。未定时间使用 null，不以 0 冒充；内部继续用整数微秒，媒体秒和 AMLL 毫秒只在边界转换。

`今日→きょう`、`宇宙→そら` 各可作为一个正文词块、多个读音单元。为连续多个词添加整体 Ruby 时，先在同一事务合成一个 base 词块；跨 Ruby 内部拆正文须同时指定读音切分点，不猜测字与读音对应。现有 mora/phoneme 结果作为映射到词/读音的附属对齐数据保留，正文坐标由当前词序列计算；不再保留旧 timingUnits 作为第二份可写词轴。

DOM 选区用 UTF-16，领域范围用 code point，用户拆分边界按 grapheme 限制；统一转换函数，覆盖 emoji、组合音标、非 BMP、日文小假名。不能在各组件零散使用字符串下标。

### 4.2 TTML 与项目边界

- TTML 继续是持久化歌词内容；编辑会话只持有一个语义文档，导入和保存时做转换。规范化已支持结构，不要求已修改节点逐字节保留原 XML 排版。
- 重写 codec 对行/词/Ruby/翻译/音译/背景歌词/agent/元数据的明确映射。先用参考工具真实导出的文件固定结构样例，再落实命名空间与时间继承；不要凭字段名猜 TTML 格式。
- 对普通行、逐字行、整体 Ruby、多段读音、背景嵌套和常见歌词属性提供编辑支持。未知扩展在导入边界记录可定位诊断；可原样携带且不影响编辑的附加属性保留，不为任意 XML 建立通用可逆编辑框架。不能理解的关键结构在导入时明确报出，不能静默扁平化后宣称保真。
- 当前外部 TTML 文件的导入支持是产品功能；旧 Studio 内部 schema、IndexedDB 快照、旧组件和旧字段兼容不是目标。切换当前 schema/cache 标识，不编写旧数据迁移、双模型同步或回退编辑器；说明旧开发草稿需重新导入，执行时不自动删用户文件。
- 复用 `useProjectDocument.ts` 的保存顺序、dirty 与冲突处理，适配新快照；项目接口仍传 TTML，非必要不新增服务。更新 `server/documents.py`、`projection.py` 对新结构的解释，保证正文投影不把翻译、注音和背景混进主唱正文。
- 本地 `/editor` 和项目路由共用组件/命令；前者使用文件与本地检查点，后者使用既有 revision 服务。不是两套编辑器互相兼容。

### 4.3 命令、选择与性能

保留命令式修改入口，按当前需求实现纯函数 reducer 和事务。增加行/词/Ruby CRUD、范围替换、拆合、移动/复制、属性批量修改、分词结果应用、打轴和时间批量处理。菜单、快捷键、右键菜单、触控按钮调用同一命令。

一次拖动在松手时提交一次，一次分词/批量替换只生成一次撤销；输入按一次编辑会话合并历史，IME 合成结束再提交。撤销恢复文档和合理的焦点/选择，不要求倒退播放时钟。采用结构共享、有界历史（先以 256 次用户操作为目标），不复制 XML 树、不在每次 pointermove 时序列化整份文件。

React Query 继续管理服务缓存；编辑状态局部提供，播放用独立时钟/订阅。默认不因参考工具使用 Jotai 就全面迁移技术栈，也不创建通用事件总线或插件式命令系统。多行 Ruby/辅助行使行高可变，替换固定 ROW_HEIGHT 的假设；优先采用成熟可变高度虚拟列表，而非自研滚动框架。

### 4.4 前端形态与复用

重建编辑页：顶部品牌/文件/菜单与三模式切换，其下按模式变化的 Ribbon，中间大面积歌词词块列表，可开关的大纲/BPM 侧栏，底部共用播放控制与可调整高度的时间轴。高级/简单布局、翻译/音译显隐、选中/播放/错误状态与参考工具一致；任务、词典、候选作为 Studio 辅助抽屉。

采用 Radix 组件建立菜单、弹窗、表单和焦点交互，CSS Modules 管编辑器布局；按需要加入虚拟列表、hyphen/假名转换和 AMLL 预览包。不整包搬入 Tauri、遥测、更新器和上游全部依赖，不为追版本升级现有构建工具。

参考工具源码带 GPLv3 声明（见其 LICENSE 和文件头），Studio 现有依赖记录明确尚未复制其源码/资源。本计划默认以行为和布局为规格重新实现；实际移植源码、样式、字体或 WASM 时，记录来源、版本和许可并保留相应声明，更新 `docs/dependency-licenses.md`。不把“参考项目能用”当作已完成依赖核查。

## 5. 分阶段工作包

顺序为 E0 → E1 → E2 → E3 → E4 → E5 → E6 → E7。每阶段交付可操作结果；E3 完成不代表“基本完全复刻”已经达成。预计单人 9–14 周，仅用于排期，E0 后按实测复杂度调整。

### E0：冻结行为与视觉基线（2–3 天）

- 启动两仓库开发环境，固定参考 commit、依赖与测试音频；记录启动限制，不联网追逐上游新版本。
- 建 `docs/editor-parity.md`：给下节每项编号，登记参考操作路径、目标行为、测试样例、状态；缺失项目必须列出，不能用总体百分比掩盖。
- 截取参考工具编辑/打轴/预览、简单/高级布局、分词弹窗、Ruby、背景歌词和时间轴。记录 1440×900、1920×1080、390×844，明暗主题及焦点状态。
- 生成双工具互读的 TTML 样例；测清字幕角色、Ruby 标时、空白、背景/对唱、翻译/音译、元数据的编码，形成 codec 映射表。
- **退出：** 操作清单和截图能作为明确验收规格；Ruby 文件能在参考工具中重新打开并保持可编辑，关键模型决策无未说明的双轨状态。

### E1：编辑文档与 TTML 闭环（6–9 天）

- 替换 `domain/document.ts`、`editing.ts`、`structure.ts`、`timing.ts`；拆成必要的 document/commands/history/text-boundaries 模块即可。
- 重构 `adapters/ttml/{codec,structure,inline-timing}.ts`，移除旧 baseline/path 驱动编辑所需的冗余副本；导入得到词块，保存按当前语义编码。
- 实现基础 CRUD、事务、选择 ID 与批量属性；接入本地/项目的同一编辑状态。更新恢复格式和服务投影，不新增旧版本兼容。
- **退出：** 无时间纯文本也能拆成词；含 Ruby、翻译和背景的 TTML 导入→修改→撤销→保存→重开语义一致；正文投影正确；每次操作有稳定 ID。

### E2：参考布局与直接编辑（6–9 天）

- 将 `Workspace.tsx` 缩为项目连接层，建立 `features/editor/EditorWorkspace`、`EditorMenu`、`EditorRibbon`、`LyricList`、`LyricLine`、`LyricWord` 与选择控制。
- 新建、插入、删除、复制、剪切/粘贴、跨行词移动，行/词拖动排序与复制；支持 Ctrl/Cmd 多选、Shift 范围、全选/反选与清空选择。内部剪贴板内容保留时间、Ruby、附属内容，纯文本粘贴有明确规则。
- 行内输入、翻译/音译输入、词时间字段、属性混合值显示；上下词定位、双击进入编辑、Escape 退出、IME 不触发全局快捷键。
- 大纲定位/排序；简单与高级布局；变高虚拟列表。两个入口均切换到新画布，删除被替换表单实现。
- **退出：** 可不打开侧栏完成常规行词编辑；选中状态、焦点和播放高亮可区分；鼠标与键盘操作同一模型，撤销能恢复排序和附属信息。

### E3：分词与批处理（5–8 天）

- 手动分词器：点击字符边界切分/取消切分、实时预览、单词拆合、单行/选中行/指定范围/全文应用。
- 自动/高级分词：CJK 按字符、西文按词或语言音节、标点合并/独立、空白处理、标点时间权重、忽略列表、自定义拆分规则、测试输入。语言列表以 E0 的 `hyphen-loader.ts` 为准。
- 已有时间按参考规则分配：保留父区间、总时长和末端，不累积舍入误差；未定时间保持未定。分词不自动重置未选中词或 Ruby，重分词涉及注音时预览明确显示结果。
- 批量替换、时间偏移、音节平滑、同步行时间戳、行结束时间链接/取消链接；明确范围及是否连带移动词/Ruby。
- **退出：** 中英日混排、连续空格、标点、忽略词、自定义规则均可预测；一键应用后一次撤销完整恢复；有时间和无时间两类歌词均通过。

### E4：Ruby 与音译编辑（6–9 天）

- 主画布显示 base 上方 Ruby 读音块，支持添加、插入、修改、删除、光标拆分、Backspace 合并、重新分配读音时间；所有单位可选中和定位。
- 实现参考工具的 Ruby 输入快捷方式（从 `parseRubyShortcut` 所在实现提取实际语法）、注音分词、由逐词音译生成 Ruby；保留手动整体读音，不依赖日语模型。
- 行音译分配到词、假名/罗马字处理、匹配问题提示；生成结果先预览再批量应用，默认不覆盖用户已有 Ruby。
- 接入现有 reading 候选/词典时将范围转换为新词块，候选过期规则保留；人工编辑无需先保存并审核才能继续打轴。
- **退出：** `今日→きょう`、`宇宙→そら`、促音/长音/拗音、纯假名、emoji 混合例可完成 base 修改、读音拆合、独立计时、撤销及双工具重开；修改某一块不清空整行计时。

### E5：打轴模式与播放控制（5–8 天）

- 增加打轴游标：lineId/wordId/rubyUnitId；有 Ruby 时按读音单元推进，父词时间由子单元更新；忽略行、背景忽略、空拍计数按参考行为执行。
- 起始轴、连续轴、结束轴、前后词/行、回听、模式切换和触控面板；快捷键可配置、显示速查并检测冲突。
- 抽取 `MediaTransport` 播放控制供模式共用：选区及前/后片段试听、倍速、循环、输入偏移和延迟校准；只设一个主播放时钟。
- **退出：** 完整歌曲可主要用键盘打轴，Ruby 不被跳过；暂停/seek/切模式/IME/弹窗/按键重复均不误写；撤销一次打轴不倒退或重启音频。

### E6：时间轴、频谱与 BPM（7–11 天）

- 在波形上建立与参考工具一致的行/词/Ruby/gap 轨道与时间标尺；拖动边界、整体平移、选择范围、吸附、缩放、滚动、自动跟随、拖动取消和跨选区批量调整。
- 区分“移动整行”与“只改边界”；间隙、重叠、空时间、行链接都有确定行为。调整 Ruby 后同步父词包络；移动行时同时移动所有子时间。
- 复用服务端媒体与 peaks；频谱在 Worker 中基于按需取得的 PCM 窗口计算/缓存，不同步扫描整首音频阻塞 UI。已有 WAV Range 能满足则不加 API；不足时仅加所需 PCM 窗口接口。
- BPM 手动输入、tap、节拍线和吸附；自动 BPM 作为此阶段后半项，独立小型分析模块接入，不移植参考工具整套 FFmpeg 播放引擎。
- **退出：** 长音频缩放/拖动无明显卡顿，拖动每次一次撤销；Ruby 子段与播放高亮一致；频谱/BPM 确实可用于定位，不能以静态示意图验收。

### E7：预览、格式覆盖与收尾（6–10 天）

- AMLL 动态预览与编辑共用当前草稿和播放时钟，支持点击定位、背景/对唱、翻译/音译、Ruby 的实际显示验证；预览设置按参考工具相关选项对齐。播放器表达不了的语义只在预览适配边界处理，不回写削减文档。
- 补齐歌曲元数据；TTML 与纯文本/LRC/ESLRC/QRC/YRC/LYS 等参考文件菜单提供的导入，以及 ASS 等导出，逐项登记实际支持方向。先 TTML 再补格式，不声称低表达力格式可无损携带 Ruby。
- 项目保存重开、本地文件工作流、当前版本草稿恢复、未保存提示、保存冲突集成；清除旧 LocalEditor、LineTable 和不再使用的属性编辑路径，保留任务/词典的必要入口。
- 完成视觉对照、全操作矩阵、长歌词性能测量，更新 README、frontend/README、验收与依赖记录。
- **退出：** 下节所有必需项有操作证据；完整歌曲制作闭环通过；延期项显式列出，不能以“后续优化”掩盖核心缺失。

视觉验收以相同音频、歌词和视口的并列截图为依据：逐项比较功能区位置、尺寸、密度、词块换行、Ruby 对齐、菜单与弹窗、选中/焦点/播放状态。品牌和 Studio 项目入口差异允许；不能用“整体看起来类似”通过。390px 下至少可完成输入、分词、注音和触控打轴，复杂 Ribbon 可滚动/折叠。

测试素材至少包含：普通中文、英文含标点/连空格、日文整体读音/多读音单元、非 BMP/组合字符、三歌手/重叠背景、行译/行音译/逐词音译、部分未定时间、相对时间 TTML、2,000 行/20,000 词及 10 分钟音频。不要依赖商业歌曲或模型下载才能运行关键测试。

关键行为：

1. 纯文本导入→分词→改错词→加 Ruby→连续打轴→拖动精修→预览→保存→刷新→导出→参考工具重开。
2. 参考工具含 Ruby/背景/翻译 TTML→Studio 修改局部→导出→参考工具验证；反向导入亦测。比较文本、边界、时间、角色和附属内容，不只检查 XML 能解析。
3. 拆合、重排、分词、Ruby、平滑、拖动分别撤销/重做，验证稳定 ID、选择定位和其他行未被修改。
4. 自动保存中继续编辑、旧响应后到、网络失败、冲突、当前格式恢复；不得把保存失败显示为成功。
5. 真实音频键盘与指针试听验证；合成媒体测试不能替代手动打轴体验记录。

性能目标（E0 实测后可附理由调整）：2,000 行/20,000 词初次可交互 ≤2 秒；普通单词编辑到可见提交 p95 ≤50ms；拖动主线程单帧工作尽量 ≤16.7ms；记录掉帧比例、机器、浏览器、生产构建、文档大小。序列化/保存耗时另测，不能沿用 S6 领域函数耗时代表整页性能。单次操作不应因全文 clone/XML 序列化阻塞。

## 7. 验证命令与交付要求

前端在 `frontend/` 运行 `npx pnpm@10.30.3 typecheck`、`test`、`build`、`test:e2e`，按变更补充 command/codec/分词行为测试和关键浏览器路径。后端有修改时用项目虚拟环境执行 `python -m pytest server/tests`（从 Studio 根目录执行），根据依赖配置记录实际通过/跳过/失败项。端到端除 mock 回归外，至少一条真实 FastAPI 保存重开路径。

本计划不要求每次 CSS 改动新增单元测试，也不要求每一步重跑所有模型任务。以本阶段风险选择验证，阶段收尾再执行相关全量检查。

每个阶段交付：可运行代码、更新的对齐清单、关键测试与真实截图/样例、明确剩余差异。以功能完成度和制作体验判断，不以组件数、测试数量或历史阶段标签代替验收。

## 8. 首轮具体切入点

先做 E0 和 E1 的一个纵向样例：在新词块模型中导入“今日も歌う / 今日→きょう”，手动拆读音、修改一个词、撤销、保存重开。随后交付 E2 主画布与 E3 分词。这样在最早两轮就能验证核心数据路径与实际输入体验，而不是先完成所有后端或建一套通用编辑框架。
