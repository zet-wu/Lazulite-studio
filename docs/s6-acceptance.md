# S6 细粒度时间与高级编辑验收

日期：2026-09-22。功能、验证和性能边界如下。

## 实现范围

- 正文与 Ruby reading 的 word/mora/phoneme 单元使用独立 Unicode code point 坐标，支持未定时间、数值修改、光标拆分、相邻合并、拖动和循环试听。读取与写回标准 TTML span 时间；正文间隙、非 BMP 字符、reading gap 与 null 不会被省略。
- 行拆合、行边界调整与整体平移走可撤销事务；行拆分没有可信时间时保留 null。正文变化清除旧单元，读音变化清除该 Ruby 的旧 reading 单元。结构事务维护行 ID 映射并使受影响审核失效。
- 组合歌手支持名称、成员和行分配；导入与编辑检查悬空引用和循环。成员持久化为 `studio:members`，不冒用 `ttm:actor` 表达成员。
- 实验 forced 对齐使用独立 Lazulite forced runner；输入来自保存且已确认的 revision，结果绑定 revision/asset。保留原始时间、整数微秒、实际粒度、引擎和坐标证据，必须人工应用。未配置模型时能力关闭；character/subword 仅作为证据展示，不伪装为音拍。
- 前端参考 AMLL TTML Tool 的三栏、紧凑侧栏和蓝色选中反馈。主 Agent 设计审查与浏览器验收，gpt-5.6-luna 子代理编写实现。

## 已执行验证

- 前端：53 项单元/集成测试通过；TypeScript 类型检查、Vite 生产构建通过。必要新增用例覆盖 Ruby/正文单元往返、读音坐标拆合、结构事务、group、候选应用和撤销。
- 服务端：25 项测试通过；覆盖已确认输入、不可变 revision、音频/时间范围、真实 HTTP 创建及获取非空 forced 任务结果。第三方库弃用提示沿用现状。
- Chromium 既有浏览器回归：5 项通过。
- 主 Agent 在真实 FastAPI + Vite 工作台运行额外浏览器验收：reading 光标拆合、数值修改、指针拖动后一次撤销、循环单元删除后退出、保存重开、最终 TTML 下载；行拆合及整体移动；组合创建、成员选择、行分配和重开。1440×900 与 390×844 无页面脚本错误、无横向溢出，时间侧栏在窄屏属性面板内可用。
- forced 浏览器闭环使用明确注入的合成后端：上传合成 WAV、确认 reading、创建任务、查看候选、人工应用、保存重开；所得 1.1–3.9 秒与后端证据一致。该验证证明协议和人工应用链路，不证明模型质量。
- 独立 codec 探针检查 `𝄞今日歌うよ` 的 Ruby base 后半单元、reading 前置间隙、未定时间、后缀部分标时、再次修改 reading、保留容器 XML ID，以及仅改行 begin 后单元绝对时间不变。未知内层样式/属性使相应行只读；双 Ruby 行拆开再合并后保留两个 XML ID，新行继承原语言属性，未定时间不继承旧边界。

## 性能与边界

本机 Chromium 开发环境，合成 10 分钟、2,000 行、20,000 个单元、约 873 KB TTML：初次解析约 632ms。12 次单行 fine timing 领域事务，局部不可变更新后中位数约 0.2ms，p95 约 26.6ms；此前全量复制路径 p95 约 880ms。测量仅含领域命令，不包含 React 提交、检查点、TTML 序列化和网络保存，不能据此宣称整页 50ms/60fps 达标。S4 已记录的端到端大文档性能仍需专门测量和改进。

可编辑 inline profile 限于已理解的简单 span 和整体 Ruby。跨越 Ruby 边界的正文单元拒绝创建；完全位于 base 内的正文单元允许。行合并要求父级、歌手和行属性兼容；语言等属性不同的行会明确拒绝合并。复杂嵌套、未知属性和未知时间语义继续保真保留并局部只读。最终导出要求行及单元完整时间和干净 profile；草稿允许未定值。

真实 Qwen 模型权重未在本次验收运行；至少两后端 PoC 和真实日语歌唱质量 benchmark 按总体方案另行完成。本阶段没有实现 S7 媒体发布，也未修改并列 Lazulite 引擎源码。
