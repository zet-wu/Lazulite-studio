# Lazulite Studio 项目架构

## 应用与职责

Studio 是浏览器前端与本地／同源 API 组成的单工作台，登录者共享一个项目库。React 19、TypeScript 和 Vite 构成 SPA；FastAPI、SQLite 和项目目录承担持久化与计算任务。Windows/macOS 桌面浏览器通过鼠标和键盘操作。

| 位置 | 职责 |
| --- | --- |
| `frontend/src/app` | 路由、会话、Query provider、错误边界 |
| `frontend/src/features` | 工作区、歌词画布、媒体、获取、打轴、卡拉 OK 和打包交互 |
| `frontend/src/domain` | 项目／歌词模型、纯命令、时间及文本规则 |
| `frontend/src/adapters` | TTML 等格式、HTTP、IndexedDB 恢复 |
| `frontend/src/shared` | 主题、图标、控件与通用显示组件 |
| `server` | 项目资源、修订、读音、模型任务、归档及媒体发布 |
| `contracts` | OpenAPI 与前端生成类型的来源 |
| `tests/fixtures` | 仓库内的可执行测试输入 |

入口为 `/projects`、`/projects/:projectId/edit`、`/login`、`/settings`；`/editor` 重定向项目列表。Workspace 组合 EditorWorkspace、保存状态、恢复与媒体生命周期，各模式共享项目草稿及播放状态。音乐可选，首次接入通过项目资源接口完成。

## 测试边界与组织

`frontend/tests/*.test.ts` 与源码旁的组件测试覆盖领域事务、格式交换、恢复及状态逻辑。`frontend/tests/e2e` 使用模拟服务验证选择、焦点、拖动、键盘和异步界面；文件以功能命名。`frontend/tests/integration` 连接独立临时 FastAPI 服务，按 `project`、`editor`、`timeline`、`media`、`vocal`、`karaoke`、`ruby`、`alignment`、`search`、`output`、`preview`、`settings` 模块验证保存重开、工程交换、资源与任务生命周期。外部搜索或计算任务可以使用显式响应夹具。

`frontend/tests/performance` 面向生产构建，验证长文档、虚拟列表、音频缓存等资源边界，显式启用诊断时附带测量数据。`frontend/tests/fixtures` 提供按内容命名的合成数据与操作助手，跨语言 TTML 输入放在根目录 `tests/fixtures/ttml`。`server/tests/browser_fixture.py` 在临时目录建立测试项目，服务退出时回收；测试不依赖开发数据目录。测试标题、夹具、项目身份与产物均按功能或行为命名。

保留能够发现行为回归的断言：原子编辑与撤销、持久化、格式交换、任务竞态、焦点及资源边界。相同布局在多个环境中的重复巡检、仅验证夹具自身规模的断言和一次性内部探针不作为常驻套件。

## 权威状态与时间

`ProjectDocument` 是唯一可编辑项目状态。`lyrics` 保存结构化歌词，`editing` 保存空拍、打轴忽略、跳过对齐和行尾链接，`acoustics` 保存分析引用及可编辑片段，`amll` 保存兼容限制，`lineOrder` 保存显示排布，`karaoke` 保存导唱、分组与输出配置。

| 边界 | 当前版本 |
| --- | --- |
| 项目 JSON | `studio-project-v9` |
| 运行时歌词 | `studio-lyric-v10` |
| HTTP 文档 envelope | `studio-document-v9` |
| 浏览器恢复 | recovery-v10／record 10（项目 v9） |
| SQLite 资源结构 | 6 |
| `.lazp` manifest | 1 |

歌词由行、词、Ruby 单元组成。主行与背景行各有稳定 ID、独立绝对时间和歌手引用；一个主行可关联多个背景。翻译与音译使用文档级有序轨道，按主行／背景行 ID 关联普通文本或定时单元，保存语言、用途及独立时间。词级歌手覆盖行级有效歌手；缺省词引用继承所属行。歌手声明可携带 `actorRef`，改名与删除维护所有引用。

时间为整数毫秒或 `null`。媒体元素的秒值、PCM 样本坐标和模型秒数在各自边界转换。TTML 相对时间先解析为实际端点再量化至毫秒，输出使用三位毫秒时钟；文本坐标使用 Unicode code point，并校验字素边界。

`project-document.ts` 执行歌词、声学与卡拉 OK 命令，统一保留 256 次项目历史。批量编辑一次原子提交。选区、焦点和播放时钟由界面状态持有；长期偏好通过服务端字段级 API 保存。

## 编辑事务

`lyric-commands.ts` 管词、Ruby、行、歌手和附属内容；结构操作同步维护稳定引用。拆行按各段词的已知端点取包络，按用户选择分配背景及附属内容。合词原样拼接文字并保留 Ruby 单元，合 Ruby 合并读音与时间包络。时间改变影响链接时，事务解除相应链接并冻结其他行当时的结束时间。

`line-structure.ts` 共享拆合行预览与阻塞条件；`editing-actions.ts` 组合选区剪贴、删除与插入。对象拖动显示副本及插入线，候选通过领域命令验证，松手提交一次。Ruby 移动以同一歌词行内的目标词为范围，保留身份、文字及时间。

`SelectionContext` 管理画布、大纲、时间轴及声学片段的有效选择；操作按对象真实归属解析范围。输入框保留原生选字与 IME 行为，虚拟列表保持活动输入挂载。显式定位先挂载目标，再按实际矩形滚动和聚焦。

`sync-editing.ts` 从有效选区派生打轴游标，连续与本行模式共享落点规则。本行模式在行末结束本次序列；词／Ruby 空拍保存在项目配置中。`shift-lines` 在同一项目事务内同步所属导唱，其他时间编辑保留导唱手调端点并通过输出校验提示范围问题。

## 注音与自动对齐

`POST /api/v1/reading/analyze` 接收当前行文本快照，Sudachi C 决定整行读音，一致 A 细分与 JmdictFurigana 资源提供可靠分段，响应使用原文 code point 范围。tokenizer 调用通过互斥锁串行执行，词典加载验证条目结构，同结构内容可替换，索引按进程缓存。前端通过唯一假名锚点保留最细可靠正文分段；默认保留原词间边界，窗口内显式开启自动合并后仅合并不可拆读音对应的最小连续汉字范围，已有注音不参与。临时提案记录源词区间，构造与重试维护不可变正文范围，人工只修改读音；应用检查源快照身份并复用合词包络及项目关联维护，不持久化子串映射。空读音跳过并取消其专属结构变化；切换开关从打开时快照重新生成并清空窗口草稿，普通重试继续保护手工输入。

`romanization-generation.ts` 按行内假名上下文生成罗马字，保留源单元与时间归属。普通和定时输出分别保存整行文本与单元。音译反向生成 Ruby 使用时间重叠提案、假名核对与人工选择；生成窗口绑定源快照，应用前校验过期和覆盖范围。

自动对齐使用随服务交付的 Lazulite 0.3.0。`alignment_projection.py` 从已保存修订投影未跳过的主行与背景行，`alignment.py` 校验项目／音源／片段并准备完整人声，`alignment_worker.py` 在受监管子进程运行日语 CTC 模型。模型目录由 `STUDIO_NEXTFIRE_PATH` 指定，词表、blank、采样率与帧映射来自适配器配置。能力检查读取轻量配置，任务内存承载声学与解码结果。

开始时固定 revision、行首提示、三个软代价开关及结果合并选项；默认软代价、清空未匹配与短空隙合并均关闭，短空隙阈值为 500 ms。服务和前端依次核对完整 scope／目标映射。当前页面持有应用意图，运行期间锁定项目编辑，成功后将时间、父包络及首次声学结果作为一次事务应用、撤销并保存。

清空策略按合法新端、缺失端和非法建议分别采用、置空或保留。短空隙合并要求同一行两侧本次采用完整合法双端、间隔大于零且小于阈值、原轴间隔被实际声学片段连续覆盖，随后延长前叶终点并统一重算包络。独立附属轨道保留自身时间。

## 播放与图形

唯一 HTMLMediaElement 提供项目时钟。原曲与人声的播放选源、图形选源独立，共享位置、0.1–2×保音高变速及 A/B 循环。A/B 捕获操作当时的有效范围。无音乐项目可进行歌词编辑与无声预览。

原曲播放代理为 48 kHz 双声道 PCM WAV；人声直接使用持久 WAV 的实际采样率与声道。API 提供 Range 播放、波形 peaks 和最多 4.02 秒的 PCM 窗口。波形／能量采用稳定预取窗口、取消过期请求并按实际覆盖区绘制。

声谱图 Worker 按 4 秒核心片、512 点 Hann FFT 计算，缓存最多 128 个强度 tile，同时最多两个请求；计算身份包含项目、音源和采样率。隐藏图层释放 Worker，过期计算由 token 与 Worker 生命周期隔离。固定颜色表表达强度，ResizeObserver 与 DPR 更新画布尺寸。测量时在挂载前设置 `window.studioSpectrumDiagnostics = true`，启用耗时、缓存计数及统计输出。

时间轴的标尺、波形、声谱图及轨道共享实际绘图区和毫秒 viewport。行、词、Ruby、定时音译、导唱和人声片段按区间分轨，拖动期间冻结轨号。吸附、预览与提交共享候选。单端未定对象用临时显示端点支持抓取，实际端点继续决定保存、播放、循环与导出。

AMLL core/react 0.5.2 按需加载，读取当前草稿的播放投影。Studio 通过五项项目兼容限制及集中校验表达外部模型差异，预览布局由播放器呈现。

## 保存、资源与任务

`useProjectDocument` 管理本地副本、dirty、revision／ETag、保存序号和冲突。IndexedDB 按稳定 library ID 分库保存当前项目及基础修订；读盘校验后创建空撤销历史。HTTP 文档中的 `lyrics.draftTtml` 承载草稿歌词；服务边界统一建模、共用一次规范化 TTML 树，校验后写不可变 JSON 修订，通过 SQLite compare-and-swap 更新当前指针。PUT 成功只返回 revision 与 ETag。草稿读取保留待修正时间，正式输出执行目标格式校验。

数据目录默认 `server/data-projects-v6`，`STUDIO_DATA_DIR` 可指定其他位置。SQLite 保存资源索引、修订指针、会话、幂等记录及任务。每个 `projects/<id>` 目录含 `source/original`、`cache`、`revisions`、`vocals`、`exports`；相同源文件在不同项目分别存储。上传在临时区校验、探测和建代理，再由创建项目／首次接入事务确认归属。

修订仅保留当前版本和排队／执行／取消未结束任务实际使用的输入；读取与入队使用同一 SQLite 事务排除回收竞争。终态结果与幂等响应保留修订身份，文件由提交、任务结束和启动恢复回收。项目删除检查活动任务，隔离目录后清理索引，失败回移；启动按数据库状态恢复。空间接口按需统计项目目录逻辑字节，分类为源音频、人声结果、缓存、快照及其他文件。

任务状态与最新阶段直接持久化；共享列表活动时每秒刷新，空闲时每 15 秒刷新，聚焦、重新进入和任务变化时主动刷新。模型任务通过独立 Python 子进程执行，API 持有队列、取消和进程回收职责；应用采用单 worker 运行以维护进程内协调。人声任务在真实阶段边界检查取消，对齐任务由监督进程管理取消与终态。

人声输入直接解码为 44.1 kHz 双声道 float32，经 Demucs 分离和必要的整曲峰值衰减后保存一份 PCM_16 WAV。分析、播放、频谱及下载共用此文件。能量来自 Lazulite `build_activity_profile` 的 `main_rms`，核心片段来自 `analyze_vocals`。每条分析以 `audio_result_id` 引用音频所有者；重分析建立独立能量与片段记录并复用 WAV。已注册结果保留至项目删除，以支持修订与撤销引用。

人声复用比较源资产、公开 Demucs 配置和生成规则；访问及复用读取 WAV 格式、位深、实际帧数、采样率与声道，音频身份由所有者 ID 管理。修订与任务通过 revision 绑定，幂等保存计算请求摘要，会话 token 以摘要存储。模型身份以配置和路径管理。

## 获取、交换与发布

歌词获取组合本地文本／文件、内嵌歌词与四个在线来源。服务负责平台请求和载荷解密，前端 codec 负责解析语义；用户预览并选择元数据后一次导入。搜索按来源限制并发，候选排序、全文缓存和取消由独立获取状态管理。

TTML codec 支持 Studio 的正文、Ruby、背景、歌手及翻译／音译表示，保留 Apple 扩展和支持的 AMLL 约定。最终输出保留歌词语义和 XML 身份，项目配置随项目保存。其他格式由各自适配器投影；`output-validation.ts` 收集格式问题并通过稳定对象 ID 定位。可导出格式和名称共用定义；歌词校验按格式筛选实际序列化阻塞，全部格式合并跨格式问题与时间警告。下载与媒体打包在执行时检查当前捕获快照；歌词下载将一次生成的内容直接交给下载器。Nicokara 校验按项目、标题和输出页选择复用准备结果。

`.lazp` 是含 `manifest.json`、`project.json` 及可选一份源音频的 ZIP。导出捕获已保存修订，清空副本的分析绑定并保留人工片段；导入检查路径、大小、唯一条目、SHA-256 和引用后创建独立项目，按需重建源音频缓存。归档写入／解包时随流计算源音频摘要，已验证摘要直接作为导入资源身份；普通音频上传同样在接收时计算一次。

`karaoke.ts` 管导唱锚点、输出组、文件选择、逐文件整数毫秒偏移与歌手标记。偏移使用分组／类型／轨道稳定输出 ID，合法提交进入一次撤销事务，随项目、恢复和归档保存；分组重命名迁移，删除分组／轨道清理。卡拉 OK 模式复用歌词画布、属性栏和独立导唱轨道；自动插入按目标组与三个阈值生成一次事务。`nicokara.ts` 输出分组正文、Ruby 及独立翻译／音译 `.kra` ZIP，非零偏移只写对应文件的 `@Offset` 标签，绝对端点先量化再计算相对标签，量化后齐平的 Ruby 省略尾标签。歌手集合绑定项目触发串与 Emoji 声明，每个 ZIP 带一份透明占位图片，实际文字与触发串冲突由输出校验定位。

媒体打包绑定已保存修订与源资产。MP4/M4A 写 STPP，并按 LRC 下拉选择写入普通／扩展 LRC 或保留源 ©lyr；STPP 与普通 TTML 共用歌词输出规则，正文、行及 Ruby 缺失端点按原样省略，定时翻译／音译仍需完整时间。输出副本结合保存修订的 editing 保留空拍、Ruby 和敏感标记空白；Unicode 分隔空白按普通 TTML 规则展开，内部草稿属性在副本中移除。MP3 写指定 USLT，FLAC 写 LYRICS；输出为独立副本。STPP 写入层验证容器结构、轨道元数据和歌词回读，完整打包在标签写入后校验最终成品：音频 packet 摘要保护实际音轨载荷与顺序，MP4 mdat 摘要及轨道快照保护原媒体和非目标轨道，标签与歌词按实际内容对照。只有通过报告的成功成品开放下载；新成功产物取代前一份可下载文件，任务记录保留，文件清理由占用情况延后重试。

## 代码与部署边界

领域层依赖纯数据与规则，适配器处理文件和服务，功能组件组合用户操作。共享主题与控件统一明暗色、按钮角色、焦点、消息及展开行为。

Vite 开发服务器通过 `/api` 代理访问 Uvicorn。生产前端为 `frontend/dist` 静态产物，由 Web 服务器提供 SPA 回退和同源 API 代理。服务精确校验 `STUDIO_ORIGIN`，密码模式使用会话 cookie 与 CSRF；受信任网关模式由部署显式启用。构建与启动命令见[README](../README.md)。


## 便携运行边界

`server/portable.py` 组装目录、文件锁、固定回环地址、实例握手及离线环境；`local_web.py` 校验 Host／Origin 并挂载生产 dist。`runtime_settings.py` 管理偏好和资料库身份，`storage_paths.py` 管理相对资源引用。领域模块不读浏览器偏好；前端 `adapters/preferences.ts` 在编辑器挂载前载入服务端值。

`runtime_devices.py` 在独立短生命周期进程探测设备，将分离／对齐快照固化到任务。CPU 重试经过旧任务归属、revision 和源音频检查；前端继续检查草稿与应用意图，成功仍通过原子项目命令应用。`process_supervisor.py` 负责模型、FFmpeg 与派生进程，JobService 在停服前封闭队列。

`vendor/Lazulite` 是固定 gitlink；计算库从该源码构建 wheel 安装，服务不拼接兄弟仓库路径。`packaging/requirements/*.in` 是候选输入，原生 `resolve.py` 输出完整带哈希锁、轮子和来源报告，并在独立环境离线安装、执行 pip check／导入。候选输入不能代替目标平台验证或发布包。

计算设备偏好由 `features/DeviceSettings` 统一读取与保存；独立设置页和编辑器设置弹窗共用控件。本机 CPU 包固定显示 CPU，其他本机包提供自动／CPU，远程服务由服务配置。编辑锁不阻止查看和修改后续任务的设备偏好，实际执行设备以任务快照为准。

SUG 项目输出由 `sug.ts` 生成每分组／附属轨道的 0.3.0 JSON 与说明 ZIP，共享卡拉 OK 输出选择、偏移及保存／恢复事务。转换保持毫秒端点，正文词包络、Ruby 首尾填满、分隔零时长和组合歌手角色在格式边界投影。格式专项问题通过源对象与输出身份定位；NicoKara 和 SUG 各自验证所选依赖，界面记录导出来源以返回正确窗口。

## 卡拉分组与搜索条件

分组窗口用独立草稿行身份承载可编辑 ID 和名称，应用时原子更新定义、行归属、输出勾选及会话自动插入目标。手动组取未占用的最小 `groupN`，新填 ID 采用英文字母起始规则并检查大小写不敏感唯一。精确 ID `main`／`background` 承担标准角色：新增行按身份寻找目标组，拆分／整行复制继承源归属；两个标准组齐备时，原标准组成员的主／背景身份切换同步组。未指定归属用空字符串保存，项目允许零个组。

歌手标记的 `skip` 按有效歌手集合配置。输出副本跳过该集合的触发串与声明并保留每文件最后输出的声部状态；参数草稿、源歌手及 TTML 保持独立。Nicokara 检查全项目未分组行，问题定位行属性；附属标签按完整翻译／音译列表编号，同语言多轨文件名使用对应 `trackN`，内部 ID 只维持引用。

`GET /api/v1/projects/{pid}/source-metadata` 按当前源音频读取标签并返回 asset 身份与三个搜索条件，复用创建项目的标签规则。显式填入通过 `useSearchConditions` 一次替换并保存整组条件；条件编辑或音频身份变化使进行中的读取失效。读取、填入、搜索分别由用户动作触发。
