# Lazulite Studio 简易教程

## 歌词获取
Lazulite Studio 支持从网易、QQ、酷狗、AMLL TTML DB 四个在线源搜索和获取歌词，并能保留其提供的词级时间和音译/翻译行。初始化项目或者首次上传音频时，会从歌曲元数据中获取标题、艺术家、专辑字段填入搜索框，标题若缺失则使用去后缀的文件名，后续也可手动修改。搜索时仅使用标题作为关键词，艺术家和专辑参与结果匹配打分。

“关联歌曲ID”可向 TTML 元数据按 [AMLL TTML DB](https://github.com/amll-dev/amll-ttml-db) 的标准写入对应网络歌曲的 ID，方便向其投稿。

## 音频分析

### 人声分离和声学分析

人声分离后，通过声学分析算法为歌曲划分为若干人声片段（界面显示为“片段”）。在“音频处理界面”，可以使用“分配”按钮，手动将某一行的时间对齐到某一片段。也可以手动调整每个片段的起止，新增或删除片段，为自动对齐做准备。

### 自动对齐

#### 对齐模型

本地包提供以下两个基于 [facebook/mms-300m](https://huggingface.co/facebook/mms-300m) 的 Wav2Vec CTC 对齐模型，符合格式和输入输出约定的模型均可兼容，将自定义模型目录复制到指定的模型目录下（本地包默认是包根目录下的 `models` 目录，可在“管理对齐模型”设置中修改），在“管理对齐模型”设置窗口中可扫描目录并显示模型列表。

- [NextFire/mms-300m-ForcedAligner-karaoke-ja-Latn](https://huggingface.co/NextFire/mms-300m-ForcedAligner-karaoke-ja-Latn)：使用日语歌唱音频后训练的专门模型，对日语歌曲有很好的对齐效果，主要的出错点常见于长音、连续相同读音；
- [MMS_FA](https://docs.pytorch.org/audio/main/generated/torchaudio.pipelines.MMS_FA.html)：通用的跨语言的对齐模型，但对齐效果不如前者，表现为起始时间大致准确，但结束时间严重偏早，因此强烈建议开启**智能延长结束时间**选项，以利用静音搜索策略和后一个词的起始时间校正前词的结束时间。

#### Studio 对齐流程及建议

自动对齐依赖人声分离的结果，如果未执行人声分离，对齐之前会自动先进行人声分离和声学分析。人声分离后，通过声学分析算法为歌曲划分为若干人声片段（界面显示为“片段”）。对齐时，使用所有人声片段拼接后送入对齐模型，因此在对齐前，可以人工删除、增加、调整片段来修正声学分析的结果或降低干扰（但一般情况下不需要自己调），在编辑界面也可以指定某几行歌词不参与对齐（勾选“跳过对齐”）。送入对齐模型的文本为歌词的正文或其注音（有注音时使用注音，没有注音时使用正文），并可选拉丁化，对齐模型不支持的输入会被跳过。**注意，不使用音译轨道。**

#### 对齐相关选项

- **前处理选项**：以下选项影响送入对齐模型的歌词文字，不会影响歌词原文。
    - **拉丁归一化**：本地包提供的两个模型均只支持英文字母的输入，因此需要启用本项。前处理会将送入对齐模型的正文或其注音（有注音时使用注音，没有注音时使用正文）拉丁化，而已经拉丁化的文字会保持原样（例如歌词中的英语，注音已有的拼音）。鉴于中日语言广泛存在的多音字/词，强烈建议在对齐之前，使用“词典注音”或“智能日文注音”功能为汉字和数字歌词标注准确、无遗漏的注音（对于日语，可以使用假名或罗马音，汉语则建议使用拼音）。
    - **去除调号数字**：本项为许多方言拼音方案所使用的后置调号、五度标记法设计，启用本项时，送入对齐模型的歌词会将每个注音/正文词单元末尾的连续数字去除（例：`soeng1` -> `soeng`）。
- **后处理选项**：以下选项影响最终写入歌词的对齐时间。
    - **清空未匹配单元时间**：启用本项时，最后向歌词写入对齐结果时，会清空所有未送入对齐模型或未得到对齐结果的单元的时间，主要是对齐模型不支持的输入，例如未开启拉丁化的汉字、标点符号、空格。
    - **智能延长结束时间**：启用本项时，将延长每个单元的结束时间，具体延长由后一个有效单元的起始、全部人声片段结束点（含内部切分点），以及 FA-Kara 细粒度能量检测得到的非静音结束点共同限定，可以大幅改善 `MMS_FA` 模型的提早结束问题。
    - **将短于阈值的行内空隙并入前词**：启用本项时，最后向歌词写入对齐结果时，延长前一个单元的末尾以消除所有短于阈值的行内空隙。
- **实验性对齐选项**：本类四项借鉴自 [MiliKara](https://github.com/BilyHurington/MiliKara) 的对齐算法，注意，笔者在有限样本上的消融测试显示这几个选项对实际对齐结果影响甚微，有时还可能有负面影响，请自行评估是否打开。

## 编辑

编辑界面支持任意单元的单选、多选、拖动，右键菜单支持批量合并（需要选中单元连续）、批量删除等操作。

### 歌手（演唱者）管理
位于编辑界面上方工具栏的“歌词设置”展开菜单，TTML 的歌词模型采用稳定 ID （如 `v1`，`v2`）管理，并可有自定义的 `name` （名称）字段，Lazulite Studio 在相关设置中优先展示歌手名称，未填写时采用歌手 ID。需要指定词级歌手时，必须在右上角设置“AMLL 兼容设置”中关闭“禁用词级歌手”（默认开启）

### 生成日文罗马音音译
从已有的注音（Ruby）生成音译轨道，预览框可直接修改生成结果。会默认高亮 `は` `へ` `を` 这三个有特殊读法的假名的生成结果以供确认，可在生成窗口的“高亮假名”中调整本次提示，关闭重开后恢复默认值。

### 从音译生成注音
从带词级时间的音译轨道，通过时间重叠的匹配，为对应的正文目标词生成假名注音，生成结果与正文相同时，该项跳过生成，未能匹配到唯一最佳正文词的音译单元会高亮提示用户手动选择目标或者跳过生成。

### 智能日文注音
不依赖于音译轨道，基于 Sudachi 和 JmdictFurigana 为正文注音（不需要 Windows 日语语言包），会自动拆分可分的正文词，并可选合并需要合并的词，预览框可直接修改生成结果。

### 词典注音
使用固定格式的词典为正文生成注音，词典的获取和格式见 [Lazulite Studio 注音词典仓库](https://github.com/zet-wu/Lazulite-studio-dict)。本地包自带汉语拼音和粤拼两个词典。

## 打轴
Lazulite Studio 的打轴交互基本参考了 [AMLL TTML Tool](https://github.com/amll-dev/amll-ttml-tool)，界面则参考了 [StrangeUtaGame](https://github.com/karaoke-studio/StrangeUtaGame)，当前打轴点所在单元在画布上会高亮显示。同时，在打轴界面通过双击打开输入框也可以编辑正文、注音，并有与编辑界面基本相同功能的右键菜单。
默认快捷键：
- 起始轴：`s`，将当前时间填入到当前打轴点的起始时间中，打轴点不前进
- 连续轴：`d`，若有空拍，消耗一个空拍，若已无空拍，将当前时间填入到当前打轴点的结束时间和下一个打轴点的起始时间，打轴点前进一个单元
- 结束轴：`f`，将当前时间填入到当前打轴点的结束时间，打轴点前进一个单元，无视空拍

可以通过右上角的设置“快捷键设置”查看和修改快捷键。

打轴界面上方工具栏可以切换“连续”/“本行”模式，“连续”即整首歌从头打到尾（跳过背景行），“本行”则在每行最后一个单元停止，使用连续轴/结束轴时不自动前进到下一行，需手动点击切换到下一行，适合配合“A/B 区段循环”使用。

## 卡拉 OK 导出
默认会将正文行和背景行分为两个分组，导出单独文件，也可在卡拉 OK 界面的“分组管理”新增、删除分组，并在行的右侧属性栏中分配分组。

翻译和音译的每一个轨道都将作为单独文件导出，在“导出 NicoKara”或“导出 SUG”窗口中可选择具体导出的分组。

卡拉 OK 界面可以在正文每一行前，以及行内词之间存在时间空白处、词内注音之间存在时间空白处插入导唱符，导唱符只在“导出 NicoKara / SUG”中使用，不进入 TTML 文件。

“导出 NicoKara”的歌手标记的实现参考了 [StrangeUtaGame](https://github.com/karaoke-studio/StrangeUtaGame) 的“分色助手”，Lazulite Studio 直接使用 TTML 的歌手属性确定导出时歌手标记的插入位置。

“导出 SUG”能够生成可以直接导入到 [Lin-K](https://github.com/karaoke-studio/karaoke-studio) 中的 SUG 项目文件，导唱符、歌手标记都使用 [StrangeUtaGame](https://github.com/karaoke-studio/StrangeUtaGame) 的原生字段。
