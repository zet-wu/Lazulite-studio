# AMLL 生成文件导入兼容

日期：2026-09-26。

Studio 的 TTML 导入现在接受 AMLL 生成器输出中的无命名空间 `head/body/metadata/div/p/span`，但根元素仍须属于 TTML 命名空间。AMLL 的 `itunes:timing` 文件按绝对媒体时间解释 `begin/end`，支持 `SS.fff`、`MM:SS.fff` 和 `HH:MM:SS.fff`；没有该标记的完整时钟时间仍按原有相对时间语义解释。未知元素、属性、DTD、超长文件和非法时间仍会报错。最终导出由 Studio 写入正确的 TTML 元素命名空间。

AMLL `iTunesMetadata` 中的逐词音译若与正文词时间完全对应，仍映射为可编辑的词音译。若音译比正文词分得更细或边界不同，则保存为行的独立定时音译轨道，避免合并时丢失原分段时间。编辑器显示这类轨道为只读；整行偏移会移动其时间，单词时间编辑不会自动调整它。空文本音译片段不产生音译内容。

`frontend/tests/lyric-codec.test.ts` 使用合成文件覆盖无命名空间结构、跨分钟绝对时间、细分音译的导入/导出和整行偏移，以及普通 TTML 相对时间。已在本机用用户提供的 38 行 MusicBox 文件额外验证导入和导出重读，正文、行开始时间及细分音译轨道保持一致；该商业歌词文件不进入仓库。
